# v0.1 A：核心契约与 Broker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立不依赖模型或 QC 软件的可安装核心，实现输入冻结、权限、幂等与可恢复控制服务。

**Architecture:** dataclasses 承载内部值对象，打包的 JSON Schema 校验进程边界；输入按确定性 manifest 冻结。单写入者 broker 使用 SQLite 事务与排他锁，CLI/RPC 只调用同一服务。

**Tech Stack:** Python 3.11–3.13、jsonschema、SQLite、TOML、argparse、Unix socket、pytest（后续实现时运行）。

**Spec:** [架构 §3–7](../specs/2026-10-21-chat-hpc-control-v0.1-design.md)、[插件协议](../../plugin-protocol-v1.md)、[总计划](2026-10-21-v0.1-implementation.md)。

## Global Constraints

完整继承总计划 Global Constraints、平台／依赖政策和类型表。项目 `chat-hpc-control`，namespace `chat_hpc_control`，插件 API `1.0`；不修改 n008。下面所有路径相对新项目根，均为后续要创建的文件。

### Task A4：事务、幂等与不确定提交

**Files:** Create `core/{store,broker}.py`, `tests/core/test_idempotency.py`, `tests/core/test_recovery.py`, `tests/fakes.py`。

**Interfaces:**
- Consumes：A1/A2/A3 类型与函数、`EnginePlugin` 经 worker 代理后的接口、`ExecutorPlugin` 注入实例。
- Produces：`StateStore.open(root: Path) -> StateStore`；`Broker.validate(task: TaskSpec, context: CallContext) -> ValidationReport`；`Broker.submit(request: SubmissionRequest, context: CallContext) -> SubmissionReceipt`；`Broker.get_status(run_id: str, context: CallContext) -> RunStatus`。
- `StateStore.reserve(request: SubmissionRequest, context: CallContext, fingerprint: str) -> Reservation` 是持久事务；`record_receipt(reservation: Reservation, receipt: SubmissionReceipt) -> None`；`list_unresolved() -> list[Reservation]`。测试假执行器只记录调用和人工证据，不作真实计算。

- [ ] **Step 1：写失败测试。** `test_same_key_once` 重放同 key 断言 `executor.submit_calls == 1` 且 run ID 相同；`test_conflict` 改 manifest 返回 `IDEMPOTENCY_CONFLICT`；`test_retry_after_environment_update` 断言重试既不 probe 又不 freeze；`test_crash_windows` 覆盖 reservation 后、native submit 后、receipt 保存前崩溃，恢复后第二次提交次数仍为一；`test_rerun` 要求新 key 与合法 rerun_of 才生成第二次执行；`test_expected_manifest_changed` 对首次提交配置漂移返回 `INPUT_CHANGED`。
- [ ] **Step 2：运行红灯。** `python -m pytest tests/core/test_idempotency.py tests/core/test_recovery.py -q`；应缺少 store/broker 行为。
- [ ] **Step 3：实现。** SQLite transactions + 唯一键 `(site_id,principal,idempotency_key)`，保存已解析请求／摘要／执行指纹与追加 events。先权限→已有 key 对照／回执→新请求核验→reservation commit→submit→receipt commit。未知提交保留 reservation；reconcile 未能证明未提交时禁止自动 submit。状态文件仅 broker 可写，文件 mode 0600，初始化拒绝覆盖已有非本项目数据库。
- [ ] **Step 4：运行绿灯。** 同一命令通过；fake 故障注入和并发请求不得重复提交；终态证据失败时标记 UNKNOWN／失败维度，不能把不确定记录删除后重试。
- [ ] **Step 5：提交。** `feat: persist idempotent reservations and recover uncertain submits`。
