# v0.1 C：GitHub、MCP 与多模型 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为同一个 broker 提供 GitHub/MCP 工具入口和 OpenAI、Anthropic、Gemini 客户端适配，并可追溯地发布结果。

**Architecture:** 输入传输先认证再生成 CallContext，模型工具参数不携带身份。客户端只转换工具与保存调用关联，所有执行写操作仍进入唯一 broker；发布是独立授权步骤。

**Tech Stack:** A/B 公共接口、HTTPX、MCP SDK 2.x、可选厂商 SDK、GitHub composite Action；默认验证使用固定协议 fixture 和模拟服务器。

**Spec:** [架构 §9–11](../specs/2026-10-21-chat-hpc-control-v0.1-design.md)、[聊天接入设计](../../chat-integrations.md)、[总计划](2026-10-21-v0.1-implementation.md)。

## Global Constraints

完整继承总计划。六工具名字和语义不变；call ID 不作幂等身份。三厂商 API 与各网页产品分别验收，不选固定模型 ID，不在计算节点存厂商 API key；不调用现有 n008 Action 或修改其部署。

## Review Focus

采用总计划五项风险。C1 验证 GitHub 身份和来源固定，C2/C4 验证主体伪造与结果提示注入，C5 验证分页／Artifact 可用性和发布未知结果。真实模型调用不是默认测试前提。

### Task C2：MCP 六工具和认证

**Files:** Create `transports/{mcp_server,mcp_auth}.py`, `tests/transports/test_mcp.py`, `tests/transports/test_mcp_auth.py`, `docs/mcp-deployment.md`。

**Interfaces:**
- Consumes：A5 ToolService/RPC、A3 CallContext 与 scope 检查。
- Produces：`create_mcp_server(service: ToolService, auth: TokenAuthenticator) -> MCPServer`；`TokenAuthenticator.authenticate(token: str, site_id: str) -> CallContext`；`serve_mcp(site: SiteConfig, transport: str) -> None`。MCPServer 来自已冻结的 MCP SDK 2.x，不使用 1.x 的旧 import 假定。

- [ ] **Step 1：写失败测试。** `test_exact_tool_set` 仅暴露六工具，无 shell/cancel/admin；`test_scope_and_owner` 无 submit scope 或跨用户 results 返回 AUTH_DENIED；`test_expired_or_unknown_token` 过期／未知 token 拒绝；`test_model_identity_field` 参数塞 principal/scopes 拒绝；`test_read_annotations` 三个结果/状态读取及 capabilities 标 readOnly，但服务端权限独立；`test_no_anonymous_remote` HTTP 配置缺认证／TLS 网关声明时不启动公网监听。
- [ ] **Step 2：运行红灯。** `python -m pytest tests/transports/test_mcp.py tests/transports/test_mcp_auth.py -q`；应缺少 MCP adapter；用 SDK 内存客户端／loopback，不接真实聊天账号。
- [ ] **Step 3：实现。** stdio 从本地 OS 身份建立上下文，HTTP 通过单独配置的短期 opaque bearer token 映射主体／scope／到期，保存 token 摘要并常量时间比对。默认 loopback，远端要求显式 TLS 网关与关闭匿名配置。网关通过受信任服务 UID 连接 broker，模型内容不能改变认证上下文。不实现或宣称 OAuth 授权服务器；网页产品若要求 OAuth 则标为尚未支持该连接方式。
- [ ] **Step 4：运行绿灯。** 同一命令通过；SDK schema 子集不能表达的检查仍在 ToolService 完整执行。断开 MCP 连接后已有计算不取消；读取输出不触发收集、发布或重算。
- [ ] **Step 5：提交。** `feat: expose authenticated provider-neutral mcp tools`。

### Task C5：GitHub 发布、Artifact 和结果访问

**Files:** Create `publishers/{base,directory,github,artifacts}.py`, `action/artifact_receipt.py`, `tests/publishers/{test_directory,test_github,test_artifacts}.py`, `tests/integration/test_publish_roundtrip.py`；Modify `core/reconciler.py`、`examples/github/qc-request.yml`。

**Interfaces:**
- Consumes：B5 CollectionRef、集合 manifest、A3 发布目标策略。
- Produces：`Publisher.publish(collection: CollectionRef) -> PublishReceipt`；`reconcile_publish(receipt: PublishReceipt) -> PublishReceipt`；`ArtifactBackend.stage(collection: CollectionRef) -> JsonObject`；`record_upload(staged: JsonObject, upload_result: JsonObject) -> PublishReceipt`；`renew(receipt: PublishReceipt) -> PublishReceipt`。续期为独立管理员／工作流入口，不加入六聊天工具。

- [ ] **Step 1：写失败测试。** `test_idempotent_publish` 同集合零额外提交/上传；`test_unknown_publish_readback` API 失败后按固定 tree/commit 读回，无法确认则 PUBLISH_UNKNOWN；`test_no_force_push` 并发更新只允许 fast-forward/reconcile；`test_bundle_tampered` 发布前任一文件被改拒绝；`test_artifact_expiry` 过期只改变下载可用性；`test_renew_append_only` 仅新回执/索引改变，旧集合字节不变；`test_credential_boundary` token 不进入 broker/worker 启动环境。
- [ ] **Step 2：运行红灯。** `python -m pytest tests/publishers tests/integration/test_publish_roundtrip.py -q`；fake API 和 Artifact 服务应因 publisher 缺失失败。
- [ ] **Step 3：实现。** 发布进程在控制网关／工作流侧，使用独立写凭据；计算站点和 plugin host 不持有该凭据。发布前逐文件核验整个集合。小文件 GitHub 固定 commit 发布，大原始包先生成带内容摘要的归档，工作流用官方 Artifact Action 上传，再将 upload ID/摘要/保留期回送记回执；实际上传 helper 不由模型参数选定。未在 Actions runtime 的环境只允许 directory 发布或现有有效引用，不能伪造 Artifact 成功。外部更新冲突先核验固定内容，再决定是否重建提交，不能改旧集合。
