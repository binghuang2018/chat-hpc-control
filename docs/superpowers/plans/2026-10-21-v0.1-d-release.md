# v0.1 D：离线兼容与发行候选 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有部署的前提下完成离线兼容、社区文档、清洁安装与本地 v0.1 发行候选。

**Architecture:** 旧身份通过只读 legacy envelope 引用；新的实现与旧队列／状态隔离。发行物只带通用代码、合成示例和公开文档，外部发布与生产迁移独立授权。

**Tech Stack:** A/B/C 发行候选、hatchling、wheel/sdist、pytest、GitHub Actions CI；英文／中文 Markdown 文档。

**Spec:** [架构 §10–12](../specs/2026-10-21-chat-hpc-control-v0.1-design.md)、[迁移清单](../../migration-checklist.md)、[发布条件](../../release-readiness.md)、[总计划](2026-10-21-v0.1-implementation.md)。

## Global Constraints

完整继承总计划。不复制私有 Git 历史／科学原始数据／商业程序；不重写旧 manifest 和 idempotency key；不连接或安装 n008，不执行迁移 M4，不自动发布公共仓库、PyPI、Action 或标签。

## Review Focus

采用总计划五项风险，并在本阶段重新核查跨版本身份、生产目录误用、wheel 内容污染与未经证实的兼容性声明。复用 A/B/C 测试证据，不把旧部署的历史通过数计入新项目。

## 默认测试范围与外部边界

后续实现的默认验证命令在新项目根执行：

```bash
python -m pytest tests -m "not qc_live and not provider_live and not github_live" -ra
```

Linux、TS 与 macOS 的适用性和 skip 必须逐项列出；默认命令成功不代表所有选配组件都实际运行。没有模型凭据、不执行真实科学计算或没有新测试仓库不会阻塞模拟层的本地交付，但会限制兼容声明。

G-Publish 前再明确许可证、远端所有者、可见性、包名与外部动作授权。若此时缺少条件，停在**本地发行候选**。n008 生产迁移不在该 Gate 内，也不因发布获准而自动获准。
