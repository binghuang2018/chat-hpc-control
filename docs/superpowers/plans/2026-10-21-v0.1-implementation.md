# chat-hpc-control v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在独立项目实现可扩展的 QC 计算控制、统一聊天工具和社区发行候选，保留现有 n008 部署不变。

**Architecture:** Python 核心负责来源冻结、授权、幂等、持久状态和结果语义；QC 引擎及执行器通过插件协议接入。CLI、GitHub、MCP 和三家模型客户端共享工具服务，计算与控制连接生命周期分离。每个站点只有一个 broker 状态写入者。

**Tech Stack:** Python 3.11–3.13、dataclasses、JSON Schema Draft 2020-12、TOML、SQLite、Linux Unix socket/flock；可选 MCP SDK、HTTPX 和厂商 SDK；pytest 用于后续实现验收。

**Spec:** [已确认架构](../specs/2026-10-21-chat-hpc-control-v0.1-design.md)、[插件协议](../../plugin-protocol-v1.md)、[聊天接入](../../chat-integrations.md)、[迁移清单](../../migration-checklist.md)。用户于 2026-10-21 确认架构；本实施计划尚待审阅。

## Global Constraints

- 项目／发行／CLI 名 `chat-hpc-control`；Python namespace `chat_hpc_control`；拟用软件版本 `0.1.0`。
- 任务 `chat-hpc-control/task/v1`、结果 `chat-hpc-control/result/v1`、工具返回 `chat-hpc-control/tool-response/v1`；插件 API `1.0`。
- entry point groups 为 `chat_hpc_control.engines` 与 `chat_hpc_control.executors`；其他层不发布第三方 Python ABI。
- 必须显式声明 `cpus`、`memory_mib`、`walltime_seconds`；`walltime_seconds: null` 表示核心与 worker 不设置计算超时。
- `idempotency_key` 的唯一范围是 `(site_id, authenticated_principal, key)`；厂商 call ID 只作审计。
- 仅 `COMPLETED + VERIFIED + COMPLETE` 可置 `data_ready=true`；默认 `scientific_acceptance=NOT_EVALUATED`。
- 人工本地登记是可选站点策略；原生 PySCF Python、ORCA、Molpro 输入不设统一分子／方法白名单。
- 原生计算与插件均为管理员授权的代码，不宣称沙箱；模型与 GitHub 凭据不进入插件／计算环境。
- 每个站点一个状态写入者；提交未知时先恢复／核对，不能盲目重算；读取不隐式收集或发布。
- 保留现有 n008 部署：本轮及本计划默认执行范围不登录／修改 n008，不触碰其服务、runner、队列、输入、状态或结果。
- 不复制旧私有 Git 历史、科研任务、商业软件或凭据。迁入代码逐文件完成权属审计；许可证未获所有者明确选择前不发布。
- Slurm、托管多租户、网页产品兼容性承诺、生产迁移均不属于本计划的软件实现默认范围。

本计划编写时仅有设计文件；用户随后批准全部实施并选择 Native。当前实现与测试状态另记，生产部署和外部发布仍不在本轮范围内。

## 2. 固定的实现选择

### 2.1 平台与依赖边界

- `requires-python = ">=3.11,<3.14"`；CI 覆盖 CPython 3.11/3.12/3.13。这是本版支持政策，非宣称更高版本不可用。
- 执行器首版支持 Linux x86_64；macOS 支持契约／客户端和离线 CLI，不承诺本地 worker、TS 或商业程序可运行。其他平台返回能力不支持。
- 核心仅引入 `jsonschema>=4.26.0,<5`；SQLite、TOML、CLI、socket、锁和摘要使用标准库。构建后端 `hatchling>=1.32.4,<2`。
- extras：`github` → `httpx>=0.28.1,<0.29`；`mcp` → `mcp>=2.3.0,<3`；`openai` → `openai>=3.35.1,<4`；`anthropic` → `anthropic>=1.17.0,<2`；`gemini` → `google-genai>=2.32.0,<3`。`dev` 包含 `pytest>=9.1.1,<10`、构建／分发检查工具及上述可选依赖。
- 上述下界来自 2026-10-21 对各包 PyPI metadata 的只读核对；只确认发行存在和 Python metadata，不代表组合依赖或运行兼容已通过。A1/C3 首次解析时生成逐环境带摘要的 constraints；若冲突先报告并调整计划中的约束，不静默换 SDK 主版本。
- 核心及其 CLI 导入不导入可选 SDK、PySCF 或商业程序；缺少 extra 时给出准确安装提示，查询已有 JSON 结果仍可用。

参考：[jsonschema](https://pypi.org/pypi/jsonschema/json)、[MCP](https://pypi.org/pypi/mcp/json)、[HTTPX](https://pypi.org/pypi/httpx/json)、[OpenAI SDK](https://pypi.org/pypi/openai/json)、[Anthropic SDK](https://pypi.org/pypi/anthropic/json)、[Google Gen AI SDK](https://pypi.org/pypi/google-genai/json)。实施时已按独立环境解析并验证可选依赖；解析记录和具体版本见发行证据。

### 2.2 状态、目录与通信

- 站点运行根由 TOML 指定；下设 `inputs/`、`runs/`、`collections/`、`receipts/`、`state.sqlite3`、`broker.sock`、`broker.lock`；示例站点 ID `example-site`，不生成 n008 配置。
- SQLite 本地文件系统，单 broker 进程写入；事务保存 reservations/runs/events/publication receipts，文件集合采用临时目录写齐、核验后原子命名。拒绝共享 NFS 状态库及两个 broker 同时持锁。
- CLI／网关通过 Unix socket 向唯一 broker 请求；只读 API 使用已观察的快照。Linux peer UID 与管理员 allowlist 确认受信任调用进程。普通本地身份由 peer UID 映射；只有明确允许的网关服务 UID 可传入网关认证的主体上下文，模型参数中无主体／scope 字段。
- MCP 远端首版采用网关预配置的独立短期 opaque bearer token，私有配置只存其摘要、到期和 scope。默认 loopback；公网部署需 TLS 网关且禁止匿名。OAuth 注册和各网页产品连接另行验证，不伪装成已实现 OAuth 服务。
- worker 使用固定安装入口，独立 session 和持久启动／终态回执；发布器保留自己的凭据。所有文件读取受站点根约束，但不把同一 OS 账号下运行原生代码称为强租户隔离。
- 模型客户端、持有 GitHub 凭据的来源网关和发布器应位于与计算进程隔离的控制环境；broker 只接收最小已核验输入。默认演示不使用真实凭据；生产若将这些进程放在相同 OS 用户／可互读环境，不得声称已保证凭据隔离。

### 2.3 公共接口冻结

公共值对象集中在 `contracts/`，由 A1 定义，所有后续任务引用这些类型，不另造同义字段：

| 类型组 | 关键字段／含义 |
|---|---|
| `TaskSpec, ResolvedTask, FrozenTask, TaskRef` | 协议定义的输入；固定来源；manifest+输入快照；`site_id/task_id/manifest_sha256` |
| `SiteConfig, RuntimeConfig, ExecutorConfig, ResourceRequest` | 私有站点、程序、调度与资源配置；资源三字段不变 |
| `CallContext, PeerIdentity, SubmissionRequest` | 已认证主体/权限/站点/传输；OS peer；固定 task+预期摘要+幂等 key+rerun_of |
| `PluginInfo, ProbeReport, ValidationContext, ValidationReport, PrepareContext` | 插件身份、探测、验证与准备上下文；参数沿用插件协议 |
| `ExecutionPlan, ApprovedExecutionPlan, ExecutorInfo, ExecutorCapabilities` | 固定 argv／清洁环境／资源；核心审批；调度器身份与约束 |
| `Reservation, SubmissionReceipt, RunHandle, ExecutionObservation, ReconciliationReport` | 持久提交身份、运行句柄、观察与不确定提交恢复 |
| `ResultContract, OutputSnapshot, ParseReport, CollectionRef, ResultPage, RunStatus` | 声明、原始快照、数值及问题、不可变集合、分页、观察状态 |
| `ToolCall, ToolResponse, PublishReceipt, CompatibilityReport` | 六工具输入／envelope、发布回执、只读旧数据映射报告 |

插件方法签名以[插件协议 §4/§5](../../plugin-protocol-v1.md)为准。所有跨进程消息先按对应 schema 解码，禁止 pickle 和任意 import。执行指纹不含结果解析器身份；更新 parser 产生新 collection，不强迫重算。

## 4. 每阶段验收与停止规则

- [ ] **G-A**：schema、来源、权限和幂等单元场景通过；CLI 在无 SDK 环境可用。
- [ ] **G-B**：独立 Linux 测试站点真实 demo/local 与三引擎 fixture 解析通过；真实 TS 验证单列为该后端支持的子条件，未执行时不能称 TS 已实测；未实测 QC 软件版本明确标注。
- [ ] **G-C**：三厂商模拟调用得到相同控制结果，GitHub/MCP 负例和不可变发布回执通过；真实 API/产品实测单独记录。
- [ ] **G-D**：旧输入身份离线对照无覆盖，清洁安装与英文 quickstart 通过，候选分发包及发布报告完整。
- [ ] **G-Publish（外部步骤）**：明确许可证、目标仓库／包名、可见性和发布授权后再公开；缺一则只交付本地候选。

任何权限放宽、摘要漂移、重试重复计算、旧数据改写或凭据进入 worker 的证据出现时，停止进入下一阶段，保留失败样本。不得用删除失败记录或重算覆盖证据来通过门槛。

本计划没有 n008 生产切换 Gate；[迁移清单 M4](../../migration-checklist.md)属于未来独立工作。即使 G-D 通过，也不授权安装或替换 n008 服务。
