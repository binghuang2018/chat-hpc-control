# 从 hpc-control 迁出：v0.1 迁移清单

日期：2026-10-21。状态：设计检查清单，不是已执行迁移记录或部署脚本。

## 1. 当前保护边界

现有 n008 部署继续使用原目录、服务、runner、队列、broker、输入登记和结果存储。本次只准备新的本地文档项目，不停止／重启服务，不更换原仓库 remote，不重命名远端目录，不重新注册 runner，不提交计算。

先创建独立社区项目，再按需接入站点。不得把原私有仓库改为公开来替代提取。社区项目仅接受经过审阅的代码与虚构／明确获准公开的 fixture，不带旧 `.git` 历史或运行数据。

## 3. 站点配置提取清单

- [ ] 将运行根、scratch、日志、输入／结果根目录、状态库位置从代码移到站点配置。
- [ ] 将 runner 用户、UID、仓库允许列表、可信主体、Issue marker 与标签策略外置。
- [ ] 将 Python、QC 程序、MPI、模块初始化、模块名、动态库和临时目录配置外置。
- [ ] 将 Task Spooler 二进制、socket、save-list、并发及 CPU/内存策略配置外置。
- [ ] 将 GitHub 发布 repo/ref、Artifact 策略和保留期配置外置；凭据独立存储。
- [ ] 社区样例采用 `example-site`、虚构仓库和路径，含明确必填项及 capability 探测要求。
- [ ] 明确 `walltime_seconds: null` 的含义；站点上限不能藏在旧代码常数中。

不能将账号／路径做全局文本替换后就认为配置已解耦；须核查命令构建、环境、工作目录、结果路径和授权判断中的实际依赖。

## 4. 分阶段迁移及退出条件

### M0：只读基线清点

- [ ] 由站点管理员确认部署源码、固定 worker、服务定义和运行环境身份。
- [ ] 清点任务 manifest、幂等映射、队列记录、进行中作业、历史结果索引与回执。
- [ ] 保存配置和证据摘要，不把密钥／许可证内容复制进报告。
- [ ] 为输入、历史结果和状态建立可验证备份，并记录回退使用的准确版本。

退出条件：能够明确“哪些记录和作业必须原样保留”。任一活动状态无法归属时停止写入迁移。

### M1：独立代码提取与来源审计

- [ ] 新仓库采用 `chat-hpc-control`；Python namespace 为 `chat_hpc_control`。
- [ ] 仅按上述模块白名单迁入必要逻辑，逐文件审查权属、私有路径、账号、结果和凭据。
- [ ] 将核心、引擎、执行器、GitHub 接入和发布边界分开；不携带科研任务或原仓库 Git 历史。
- [ ] 决定并落实开源许可证，审计第三方代码和依赖许可。
- [ ] 使用合成输入、脱敏原生输出及一个第三方 demo engine 验证扩展边界。

退出条件：新机器仅通过站点配置可运行，且核心不依赖原站点路径、账号或现有任务。

### M2：兼容和离线对照

- [ ] 旧 Issue marker／任务名称由 legacy adapter 映射，不强迫旧客户端立即升级。
- [ ] 原 manifest、旧 canonicalization、哈希和状态 key 保留；新对象通过 legacy envelope 引用旧身份。
- [ ] 新任务使用独立 schema 和命名空间，不能与旧 Issue key 冲突。
- [ ] 对相同只读输出快照比较新旧解析结果；差异单独报告，不覆盖旧集合。
- [ ] 验证重复请求、不确定提交、重启后的队列号复用、发布 readback 和 Artifact 续期。

退出条件：既有可用结果不退化；不支持的旧记录保留原状并明确标识，不能猜测迁成成功。

### M3：无提交旁路与独立 canary

- [ ] 先只读旁路观察；新进程没有旧队列提交权，不触碰旧状态。
- [ ] 试运行采用新 site ID、新状态根、新队列 socket/实例和新结果根，避免两个 broker 双写。
- [ ] 使用新任务和授权用户试验；不把旧进行中任务再提交到新队列。
- [ ] 明确真实输入许可和实际计算成本；经授权后再运行原生 QC canary。
- [ ] 分别证明终态、原始文件完整性、声明完整性与权限；科学验收另列。

退出条件：重复调用不会产生新计算，故障恢复可解释，canary 结果及回退经过独立记录。

### M4：可选生产切换

- [ ] 列出具体迁移目标、要修改的服务／目录／权限与回退步骤，获得本次切换授权。
- [ ] 先停止旧入口接受新任务，保持已运行 worker；确认唯一提交写入者。
- [ ] 有活动作业时继续由旧观察链负责，或通过已验证的只读句柄桥接；不能复制队列号后直接接管。
- [ ] 切换入口、读取固定状态映射，核对 runner 身份和凭据范围。
- [ ] 保留旧实现、配置和证据，直到保留期与回退条件满足；不自动清理旧数据。

退出条件：新请求进入目标实例，旧任务仍能归属并读取，重复请求不重算，回退不覆盖已发布结果。

## 5. 回退原则

在 M0–M3 发现异常，停止新实例即可，旧部署不变。M4 后回退须先冻结新入口并盘点新侧进行中作业，保持各运行的唯一所有者；恢复旧入口时保留新侧 run 映射，不能把新请求全部重放。

回退不删除已生成的合法任务／结果，不重写历史状态和集合版本，不把无法确认的提交标成失败。涉及 root 的服务安装、用户、权限或系统配置仍由用户在节点手动执行，本项目当前文档不包含自动执行这些操作的命令。
