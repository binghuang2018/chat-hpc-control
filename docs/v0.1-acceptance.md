## Independent review and repairs

A fresh-context reviewer examined the whole implementation, then checked repairs
and release tooling. Confirmed issues were reproduced before repair:

1. Runtime identity could drift while a local worker waited for a slot. Approval
   is now repeated after the wait and immediately before native launch.
2. A fetched GitHub body could differ from its authorized event. Exact body and
   request-label binding now rejects stale event attribution.
3. Disabling a historical engine could crash startup reconciliation. Existing
   collections remain readable; an unavailable parser is a per-run capability gap.
4. Git source count/total bytes were checked too late. Count is preflighted and
   cumulative bytes are checked during reads.
5. Raw output >64 MiB was incorrectly limited by the numerical parser reader.
   Raw publication uses verified inventory sizes; parser limits stay explicit.
6. Reusing an evidence name could associate an old PASS with a new failed log.
   Evidence files are write-once, log hashes are bound at capture, source-changing
   runs cannot create PASS, and the release manifest rejects changed logs.

Additional regression-led hardening covered bounded/FIFO reads, archive Unicode
and decompression limits, output declarations/root links, worker HOME/TMP, explicit
runtime/MPI files, and direct Gemini credential/retry configuration. Packaging
checks caught and repaired an unanchored sdist selection that included ignored
development dependencies. An ignored-file tripwire now exercises that case even
on a clean checkout. No remaining mandatory review finding is outstanding.

## Explicit qualifications and unexecuted work

- **NOT RUN:** real model APIs, ChatGPT/Claude/Gemini product connections, real
  GitHub workflow/Issue/commit/Artifact operations, and public package publication.
- **NOT RUN:** real PySCF/ORCA/Molpro numerical jobs, commercial licenses/MPI builds,
  and systemd service installation. QC coverage is launch contracts and original
  synthetic parser fixtures, not software-version or scientific certification.
- Native execution is supported on **Linux x86_64**. macOS support is core/client.
  Memory is advisory; CPU affinity is initial, nonexclusive. Trusted native Python
  and plugins are not a tenant sandbox. External cgroups, disk/host loss and
  supervisor behavior require site deployment validation.
- Null walltime has no framework calculation deadline. Chat/control budgets do
  not cancel native computation; explicit site caps reject incompatible requests.
- Whole installed plugin distribution identity conservatively includes parser
  code. A parser-only update may change **new validation manifests**. Existing
  intent retries retain their receipt; terminal reparsing creates another immutable
  collection without rerunning native work. Independent execution/parser package
  attestations are a future protocol improvement.
- PySCF JSON is script-reported. ORCA certification profiles are deliberately
  narrow RHF singlet cases; unsupported/ambiguous evidence remains unverified.
  Molpro XML support is a conservative synthetic subset, not universal native XML.
- Publication currently materializes bounded payloads in memory. A site's raw byte
  budgets must fit the gateway; this is not an unlimited streaming data service.
- Numerical completeness and verified execution do **not** establish scientific
  validity. Scientific acceptance remains **NOT_EVALUATED** unless independently
  evaluated under a scientific protocol.
